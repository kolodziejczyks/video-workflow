# Issue tracker: GitHub

Issues and specs live in kolodziejczyks/video-workflow.
Use connected GitHub tools, or the gh CLI when available.

“Publish to the issue tracker” means create a GitHub issue.
“Fetch the relevant ticket” means read its body, labels and comments.

Use native sub-issues and blocking dependencies when supported.
Otherwise record “Part of #N” and “Blocked by: #N” in ticket bodies.

PRs as a request surface: no.
